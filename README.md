# Steadyship

An engineer in the conversation for non-technical people building business
software with AI. Steadyship is a Claude plugin: it asks what you don't know
to ask, judges what you can't judge, and gives prototypes a path to software a
business can run on. See `docs/proposal-v0.1.md`.

## Try it in 10 minutes

1. Add the Steadyship plugin. In **Claude desktop**: Customize → Plugins →
   Add marketplace → enter `cookc/steadyship` (from GitHub) → install
   **steadyship**. In **Claude Code**: `/plugin marketplace add cookc/steadyship`
   then `/plugin install steadyship@steadyship`. The repository is private: the
   GitHub account Claude is connected to must have access, or adding it fails
   with 'not found'.
2. Choose a folder to work in (any empty or scratch folder), then say:
   **"Try Steadyship with the demo business"**
3. Then say, one message at a time, in order:
   1. "Run steadyship status"
   2. "run spike 0"
   3. "run spike b"
   4. "What apps do we have and where is the same information kept twice?"

The last question is answered by Claude reading the demo with Steadyship's
context — Steadyship's own assessment skill is being built; today's baseline is
in `docs/judgement-spike.md`.

That is the whole quick start. No terminal needed.

## Set up for your own business

Say **"Set up Steadyship for <your business>"** and answer the questions.
Creating the private GitHub repository is an optional last step; it only
happens if you say yes.

## What you get

- A repository of your own, self-contained (it works without the plugin).
- A status check: what apps you have, what each is for, what is at risk.
- Go/no-go "spikes": short checks of what your environment can really do.
- An assessment path for each app, from prototype to something runnable (assessment skill: in progress).
- Plain-language answers, such as where the same information is kept twice.

## Layout

- `plugin/` — the Claude plugin: skills (`steadyship-init`, `steadyship-demo`,
  `steadyship-status`, `steadyship-spike`, `steadyship-assess`), the scaffolder `scripts/init.sh`, `templates/`, and
  `demo/` (the mock customer).
- `.claude-plugin/marketplace.json` — this repo is also the plugin marketplace.
- `tests/test-init.sh` — generates a customer repository and checks it works.
- `tests/judgement/` — judgement eval harness (assess/ask/review on Demo Boatworks,
  with and without the plugin). Run `tests/judgement/run.sh`; see
  `docs/judgement-spike.md`. It costs money and minutes, so it is deliberately
  not in `scripts/validate.sh` or CI (there is no `--judgement` flag there).
- `scripts/validate.sh` — every product check CI runs.
- `docs/` — proposal, plans, and `rehearsal.md` (what to test where).

## Customer repositories

Each business gets its own repository, generated by `steadyship-init` from
`plugin/templates/`, owned by the business, and self-contained.

## Demo customer

`plugin/demo/` is a mock customer (Demo Boatworks): six prototype apps,
shared-drive files and business docs; see `plugin/demo/README.md`. Its answer
key is `tests/judgement/answer-key.md`, kept outside the plugin.
The `steadyship-demo` skill builds it for anyone. Maintainers:
`scripts/demo-regenerate.sh` rebuilds the standing demo repository from it.
